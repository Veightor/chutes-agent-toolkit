## Endpoints

### 1. POST /generate

- Base URL: `https://vonkaiser-minimaxh3fl2va.chutes.ai`
- Output content type: `video/mp4`

Request fields:

- `prompt` (string, optional) Default: "A red fox trotting through a snowy pine forest, snow crunching underfoot.".

Example call:

```bash
curl -X POST "https://vonkaiser-minimaxh3fl2va.chutes.ai/generate" \
  -H "Authorization: Bearer $CHUTES_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
  "prompt": "a serene mountain lake at sunset",
  "seed": 42,
  "duration": 5,
  "aspect_ratio": "16:9",
  "num_inference_steps": 30
}' \
  --output output.mp4
```

## Model Facts

- Modalities: text, image in → video, audio out
- Modes: text-to-video, first-frame image-to-video, last-frame, first+last interpolation
- Output: MP4, H.264 video + AAC 32 kHz stereo audio (audio always generated, no flag), 24 fps, 768p short side
- Precision: NVFP4 transformer + NVFP4 text encoder (torchao), FA4 attention, single RTX PRO 6000
- Pricing basis: $1.80/hr GPU rate, billed per compute-second (from the model-page OpenAPI `x-chutes.pricing`)
- Confidential compute: yes (`confidentialCompute: true` in the model-page OpenAPI)

## Full request schema (POST /generate)

| Field | Type | Constraints | Default |
|---|---|---|---|
| `prompt` | string | required, 1–7000 chars | — |
| `first_image_b64` | string | optional, raw base64 image — first-frame conditioning (I2V) | null |
| `last_image_b64` | string | optional, raw base64 image — last-frame conditioning | null |
| `duration` | int | 4–10 seconds | 5 |
| `aspect_ratio` | enum | `21:9` `16:9` `4:3` `1:1` `3:4` `9:16` | `16:9` |
| `num_inference_steps` | int | 10–50 | 30 |
| `seed` | int | optional, 0–2³²−1 | null (random) |

Resolution per aspect ratio (fixed, no width/height fields): 21:9→1536×672,
16:9→1344×768, 4:3→1024×768, 1:1→768×768, 3:4→768×1024, 9:16→768×1344.
Frame count snaps to a 17n+5 grid (120–360 frames @ 24 fps).

## Operational notes (verified live 2026-08-06)

- The render is synchronous — the HTTP connection stays open for the whole
  generation. The chute source references an 1800 s cord limit, but the public
  ingress returns **HTTP 504 after ~600 s** (measured: an 8 s / 30-step render
  504'd at exactly 600.2 s, nginx via Google LB). Always check the response
  status + `Content-Type: video/mp4` — a 504 hands you a 160-byte HTML page
  while curl still exits 0.
- Measured render time: **272 s** for the minimum-length clip (124 frames ≈
  5.2 s output) at 20 steps, 16:9, running solo. Instances serialize renders
  on a per-GPU semaphore and queue time counts toward the 600 s edge window:
  two concurrent requests at this size both 504'd. Send media requests one at
  a time and keep `duration × num_inference_steps` modest.
- `duration: 4` and `duration: 5` produce identical output — both snap to the
  124-frame floor (5.17 s at 24 fps). Verified output: H.264 1344×768 (16:9)
  + AAC 32 kHz stereo, ~0.9 MB for the minimum clip.
- `first_image_b64` verified live: a ~135 KB JPEG sent as raw base64
  (~183 KB string) was accepted, and the output's first frame matched the
  conditioning image nearly pixel-for-pixel; render time was unchanged
  (289 s at the minimum-clip config). `last_image_b64` is documented in the
  chute source but has NOT been exercised live (BETA).
- Out-of-range values (e.g. `duration: 99`) are rejected with HTTP 400
  `"Invalid input parameters"` — the error does not name the offending field,
  so validate against the table above before sending.
- An empty body returns `"exhausted all available targets to no avail"` (the
  instances reject it), not a schema error listing required fields.
- `GET /openapi.json` on the chute host proxies to the management API — it
  does NOT describe this chute. Use the model-page openapi.json or the chute
  source (see above) instead.
